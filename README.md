# be3600pro-mihomo

在 **小米 BE3600 Pro（RN01）原厂系统**上运行 Mihomo，通过 Android App 在家庭局域网管理代理。

**当前是预览版本。实机验证对象只有 RN01、原厂固件 1.0.74、默认 LAN `192.168.31.1/24`。BE3600、其他型号、其他固件和自定义 LAN 均未验证。** 工具会拒绝未经验证的型号或版本；项目不刷固件、不修改启动分区、不修改 root 密码。

## 提供什么

- 原厂管理密码登录、密钥 SSH 获取和环境检查工具。
- 私有配置生成、原厂配置备份、部署计划、初次安装及保留配置的卸载工具。
- Mihomo 内存运行：配置保存在路由器，内核不占用有限的持久闪存。
- 重启时校验官方基础内核并应用本地二进制差分补丁；失败时保持普通路由，可由 Android App 上传内置恢复包。
- 原生 Android 管理 App：HTTPS 配对、状态、规则/全局/直连模式、节点选择、添加/更新/删除订阅、直连设备多选和离线恢复。
- IPv4/IPv6 TCP、UDP 透明代理。UDP 源端口碰撞修复的完整源代码补丁和测试随仓库提供。
- 开启代理时保留原有普通 TCP 连接；新连接才进入代理，已有透明代理连接继续接收数据。
- 解析已配置节点的地址与端口，按端点直连，避免 LAN 设备自己的 Clash 再次经过同一上游节点；不会整机豁免设备。
- 限时启用回退、核心/管理服务健康检查和故障时撤掉接管；配套低负载采样与实机诊断工具。

## 运行方式

```text
Android App ── 局域网 HTTPS 9443 + 证书指纹/令牌 ── 管理服务
                                                        │
家庭设备 ── 原厂路由 / 按规则透明接管 ── 内存中的 Mihomo ── 上网
                                                        │
                       /data/codex-router：配置、密钥、恢复差分
                       /tmp：内核、管理程序、规则运行缓存
```

管理 API 绑定 `192.168.31.1`，Mihomo 控制接口绑定 `127.0.0.1`；防火墙限制管理端口从家庭 LAN 访问。App 不提供公网远程管理，也不是手机 VPN。

## 从这里开始

完整命令见 [安装与恢复](docs/quickstart.md)，工具与构建方式见 [开发说明](docs/development.md)，实测范围与限制见 [验证记录](docs/validation.md)。

基本顺序：

1. 保持路由器使用原厂系统，确认固件版本、默认网段和联网校时正常。
2. 用 `scripts/router-access.py` 检查设备并获取局域网密钥 SSH。
3. 导出自己的完整 Clash/Mihomo 配置，生成私有路由器配置与规则缓存。
4. 构建管理服务、获取校验过的 xtables 扩展、恢复固定版本内核。
5. 查看安装计划，执行初次安装；初次安装结束时代理保持关闭。
6. 在 Android App 导入私有配对文件，选择节点和模式后开启代理。

**不要把自己的配置、节点密码、订阅链接、配对文件或签名密钥提交到 Git。** 默认输出目录 `private/`、`work/`、`build/`、`logs/` 均已忽略。配对文件包含局域网管理权限，不是可公开分享的示例文件。

## 验证状态

已完成 RN01 上的双栈联网、UDP 回包与端口碰撞测试，Android 实机安装及配对，订阅后端事务测试、直连设备界面，以及 TCP 接管切换前后的连接连续性对照。核心和管理服务故障回退均在实机触发验证。

**公开的初次安装器尚未在另一台恢复出厂的路由器上完成全流程验收；重启后的自动下载恢复尚未完成实际重启验收。** 已有设备只验证了安装器拒绝覆盖现有服务的保护路径，以及启动入口的手动执行。不要把这些结果理解成所有环境下的长期稳定性或游戏兼容性保证。

开启接管会保留旧的普通 TCP 连接，因此旧连接会在自然结束后才跟随后续代理规则。关闭接管会立即恢复普通路由，已经通过代理建立的部分连接可能需要应用重连。

# 稳定性与故障恢复（0.3.0 预览）

适用范围仍是 RN01 / 原厂 1.0.74 / 默认家庭网段。本文描述实现契约；真实重启、拔电、其他硬件和新版 Android 界面验收不能由 CI 代替。

## 1. 急停优先

App 顶部“急停”使用独立执行器，不受订阅更新或核心上传的 busy 状态限制。已排队的旧任务会被取消；请求携带操作开始时的 `X-Intent-Epoch`，迟到的旧启用请求会收到 409。旧客户端不带此字段仍兼容，不能得到同等的客户端排队保护。

`POST /api/emergency-stop` 和 `POST /api/enabled {"enabled":false}` 均独立于普通写操作锁。先取消旧操作、更新持久意图，再在短期本地规则锁中撤掉接管。急停不停止待命核心；不承诺保留当前透明 TCP 会话。SSH 可执行 `sh /data/codex-router/routerctl.sh disable`。

普通 HTTP 超时不等于撤销成功；急停有专门的取消语义。内核文件恢复可以完成安全收尾，但不能恢复旧的启用意图。

## 2. 开机恢复

bootstrap 使用内核 flock，不依赖“PID 文件还在所以正在运行”的假设。文件描述符在进程退出后释放；启动的服务和 Dropbear 不继承 bootstrap 锁。

每轮最多 6 次尝试，每次按顺序尝试 GitHub 官方 release API 和官方 release 下载地址；每次下载最多 60 秒、32 MiB，全部入口须通过同一归档 SHA-256，解压基础内核、差分补丁和最终二进制也分别验证。失败后按 5、15、30、60、120 秒退避，不无限快速重试。耗尽后保持普通路由；可在 App 重试下载或离线上传。没有第三方镜像或个人 GitHub token。

下载阶段不锁住离线恢复。最终安装才与 App 共用 `core-install.lock`，并再次检查是否已由 App 恢复。`bootstrapStage` 和 `bootstrap-error` 供状态页说明恢复进度。此实现仍依赖官方源、可用 RAM 和正确校时；App 恢复包是离线替代路径。

## 3. 健康分层

- watchdog 保留原有本地核心/管理服务连续失败回退；约每 15 秒检查一次双栈接管完整性，连续两次本地规则检查失败后撤掉接管并保存关闭意图。
- 本地完整性检查核对两族的入口跳转、transparent-socket TCP、SYN TCP、UDP、TCP/UDP DNS REDIRECT、精确 fwmark 策略规则和 table 166 的本地路由。锁忙返回“检查暂不可用”，不能计为通过。
- agent 缓存健康快照，每约 30 秒更新本地状态；超过 90 秒或与当前启用状态不符即标为过期。
- 约每 5 分钟运行小流量 DNS、直连 HTTPS、混合端口 HTTPS 和双栈 [SOCKS5 UDP](https://www.rfc-editor.org/info/rfc1928/) / [STUN](https://www.rfc-editor.org/info/rfc8489/) 诊断。UDP 验证随机事务 ID、成功响应类型、cookie、长度和不分片的 SOCKS 数据报。它验证混合端口选路，不能替代客户端 TPROXY、游戏或所有公网目标验收。
- 外部探测是参考信息，不触发全屋关闭或节点切换。单次超时不能定位路由器、节点、运营商或目标的责任。

## 4. 上游端点刷新

每约 5 分钟重解析当前配置和受管订阅节点，8 个并发解析 worker、10 秒总 DNS 预算、最多 2000 个主机/8192 个端点。豁免严格保持“目标 IP + TCP/UDP 端口”，不豁免整台客户端或整段目标网段。

IPv4/IPv6 分别缓存最后成功解析，使用开机 uptime，缺失地址族或 DNS 失败只保留原时间戳，最多 1 小时。删除的主机立即从下一次计划消失。DNS 截止也要完成所有主机的过期评估。

先填充私有临时 ipsets，再在生命周期锁内 swap 两族，第二族失败会尝试恢复第一族。它不是跨两个内核集合的同时提交，但不会先清空 live 集合。每个条目还带剩余 TTL，刷新持续失败时内核仍会到期清除。初次从旧版升级须关闭/重新开启代理，迁移不带 timeout 的旧集合；不能直接与不同参数的旧集合交换。

## 5. 可选故障切换

默认没有任何自动策略。用户可为最多 2 个手动策略组各选择 2–4 个独立代理节点。每约 5 分钟检查，仅当前选择也在候选内时工作；当前节点连续两次检查失败后才测试候选，切换后冷却 10 分钟，不自动来回抢回首选。切换结果保存到节点选择状态，保存失败则尝试恢复原节点。

用户手动选节点会先停用该组自动策略。当前家庭部署不自动开启此功能。现有 TCP 无法无缝迁移；应用可能需要重连。节点延迟测试使用固定 HTTPS 204 目标，仍不能代表某个游戏的 UDP 可用性。

## 6. 后台订阅任务与绑定

`POST /api/jobs` 接受带随机 `key` 的 subscription-add/update/delete。相同 key + 相同输入返回同一任务，不同输入返回 409；最多 8 个未结束任务、32 条内存记录，结束记录最多保留 1 小时，容量满时可提前淘汰最旧结束记录。重启会丢失任务历史。

查询：`GET /api/jobs/{id}` 或 `/api/jobs/by-key/{key}`。状态为 queued/running/succeeded/failed/cancelled；失败不会伪装成成功。App 仅持久保存随机任务 key，订阅 URL 不放普通 preferences。断开后先查询上次任务；历史丢失时提示检查订阅后再提交，避免盲目重发。

导入的内联节点可用 `/api/imported/preview` 预览绑定原始订阅，10 分钟有效、最多两个预览。`/api/imported/apply` 需要一次性 token、匹配配置摘要及缺失节点确认；旧 token、配置变化或急停后拒绝应用。名称匹配的选择保留，消失节点从组候选和保存选择移除；空候选组使用 DIRECT，需用户在预览时明确确认。未确认删除的日常订阅更新返回 409，要求重新预览。最多 10 个来源、2000 个总节点。

解除导入订阅的绑定保留当前内联节点；删除普通受管订阅会移除其来源和节点。

## 7. 诊断与已知配置恢复

`GET /api/diagnostics` 使用字段白名单，仅导出版本化状态、计数和有限健康枚举，不含配置、节点名、地址、设备身份、日志、令牌或证书。App 可查看和复制 JSON。它不等于完整日志取证包。

配置事务前自动保存旧配置；`POST /api/backup` 可手动更新本地备份，`GET /api/backup` 仅返回可用性和时间，`POST /api/backup/restore` 恢复。备份包含必要的订阅缓存，gzip 最大 512 KiB、解压最多 8 MiB，权限 0600，留在路由器，不通过诊断 API 导出。凭据仍在本地备份中，因此它不是可公开文件。

恢复先关闭接管，校验并事务加载配置/状态，恢复两种节点缓存；失败回滚原配置和当前选择，成功仍保持关闭。事务在 reload 前发布匹配的配置与状态，回滚也先发布匹配的旧文件，避免“磁盘选 A、核心实际选 B”。

## 验证与边界

离线测试覆盖急停竞争、过期请求、真实 shell 锁/规则生成、下载重试/错误哈希、缓存 TTL/全局超时、异步任务重试/取消、订阅预览、备份损坏/选择回滚，以及本地 SOCKS5 UDP 故障模拟。CI 增加 `tests/resilience`；Go race/vet、ARMv7、完整 Android 构建和已有隔离 Linux UDP 测试继续运行。

实机部署与压力测试结果另行记录，不把通过这些测试表述为任意流量零损耗、任意游戏无卡顿或真实重启验收。更新 App 仍需连接手机安装，原配对可沿用。
